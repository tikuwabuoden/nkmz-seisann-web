# V1 機能仕様（ドラフト）

更新日: 2026-07-18  
関連: GitHub Issue #1（要求整理）、#2（FE技術選定）

## 1. 目的と対象範囲

旅行、飲み会などの共同立替をスマートフォンから記録し、参加者間で必要な最終送金を分かりやすく提示する。

V1は精算グループごとの精算記録と送金案の表示までを対象とする。実際の送金、支払い確認、Walletイベントの作成は対象外とする。

## 2. 用語

| 用語 | 定義 |
| --- | --- |
| 精算グループ | 旅行、飲み会などの共同精算をまとめる単位。名称のみを持つ。 |
| 参加者 | 精算グループに所属する、nkmzへDiscordでログイン済みのユーザー。 |
| 費目 | ひとつの支払い・立替の記録。 |
| 立替者 | 費目の支払いをした参加者。ひとつの費目に複数指定できる。 |
| 負担対象者 | 費目を負担する参加者。重みが0より大きい参加者を指す。 |
| 立替額 | 参加者が実際に支払った金額の合計。 |
| 負担額 | 分担計算の結果、その参加者が負担すべき金額の合計。 |
| 差額 | `立替額 - 負担額`。正なら受取、負なら支払いが必要な金額。 |

## 3. 利用者と認可

- 利用にはnkmzのDiscord OAuthログインを必須とする。
- 精算グループの参加者だけが、その精算グループを閲覧・操作できる。
- 参加者全員に同じ権限を与える。精算グループ、参加者、費目は誰でも作成・編集・アーカイブできる。
- 認証、精算グループ参加者の認可、入力検証はnkmz（BE）が最終的に判定する。
- FEはCookie付きのnkmz公開HTTP APIだけを利用し、DBやWalletテーブルへ直接接続しない。

## 4. 精算グループ管理

### 4.1 精算グループ一覧

- ログインユーザーが参加しているアクティブな精算グループを一覧表示する。
- 一覧から精算グループ詳細を開ける。

### 4.2 精算グループの作成

- ログインユーザーは名称を入力して精算グループを作成できる。
- 作成者は作成時点で最初の参加者になる。
- 種別、日程、場所、説明、画像はV1では持たない。

### 4.3 精算グループの編集・アーカイブ

- 参加者は精算グループ名を変更できる。
- 参加者は精算グループをアーカイブできる。
- アーカイブ済みの精算グループは通常の一覧に表示しない。アーカイブ一覧から閲覧と再表示ができる。
- V1では精算グループを完全削除しない。

## 5. 参加者管理

- ログイン済みユーザーだけが、nkmzユーザー名の部分一致で参加者候補を検索できる。
- 検索結果は最大10件とし、画面にはnkmzユーザー名だけを表示する。
- 検索APIは参加者の登録に必要な内部ユーザーIDとユーザー名だけを返す。Discord ID、パスワード、登録日時などは返さない。
- 検索結果から追加したユーザーは、以後その精算グループを閲覧・操作できる。
- 精算グループに所属できる参加者は、有効・無効を合わせて最大20人とする。
- 新しい費目の作成時、アクティブな参加者を負担対象候補にする。
- 既存費目に含まれない参加者は精算グループから外せる。
- 既存費目に含まれる参加者を外すときは削除せず無効化する。無効化した参加者は既存費目・過去の精算結果には残し、新しい費目の候補には出さない。
- 無効化した参加者は再度有効化できる。
- 自分自身を精算グループから外すことはできない。

## 6. 費目管理

### 6.1 費目の属性

| 属性 | 必須 | ルール |
| --- | --- | --- |
| 内容 | 必須 | 支払い内容を表す1行テキスト。 |
| 総額 | 必須 | 1円以上の整数JPY。 |
| メモ | 任意 | 補足テキスト。 |
| 立替内訳 | 必須 | 1人以上の立替者と、それぞれの支払額。 |
| 負担内訳 | 必須 | 参加者ごとの重み。重みは0以上・小数第2位までとし、0より大きい参加者を1人以上含める。重みが0の参加者は負担対象外とする。 |

### 6.2 登録・編集・削除

- 参加者は費目を新規登録、編集、削除できる。
- 作成時は、立替者の重みを1とする。その他の候補参加者の重みは0とし、利用者は必要に応じて直接入力で変更できる。
- 立替者はアクティブ・無効を問わず、既存費目では表示・編集できる。ただし新規費目ではアクティブ参加者だけを候補にする。
- 立替内訳の支払額合計は総額と完全に一致しなければならない。
- 費目の編集・削除後は、全参加者の集計と送金案を再計算する。
- 返金・割引を別の負の費目として登録しない。元の費目を編集または削除して訂正する。
- 費目の変更履歴は保存しない。
- 同じデータを複数人が同時に編集した場合は、最後に保存された内容を採用する。
- すでに削除された費目を保存しようとした場合は、エラーとして扱う。編集内容の自動マージや競合解消画面はV1では提供しない。

## 7. 分担計算

### 7.1 入力条件

- 金額はJPYの整数円のみとする。小数、外貨、負数は扱わない。
- 重みは0以上の10進数とし、小数第2位まで入力できる。重みが0の参加者は負担対象外とする。
- 各費目には、重みが0より大きい負担対象者を1人以上含める。
- 分担計算では、重みを浮動小数点数ではなく10進数として扱う。
- 均等割りは、全員の重みを1にした重み付き分担として扱う。

### 7.2 計算式

費目総額を `T`、重みが0より大きい負担対象者 `i` の重みを `w_i`、重み合計を `W` とする。重みが0の参加者は計算対象に含めない。

1. 各負担対象者に `floor(T * w_i / W)` 円を配分する。
2. 残った円（`T - 配分済み合計`）を、1円ずつ配分する。
3. 配分先の優先順は、まず立替者ではない負担対象者を精算グループへの参加順に並べる。全負担対象者が立替者である場合は、負担対象者全員を精算グループへの参加順に並べる。
4. 残額が優先順の人数を超える場合は、先頭から同じ順で繰り返し配分する。

計算結果の負担額合計は必ず費目総額と一致する。

### 7.3 個人別集計

- 立替額は、立替内訳におけるその参加者の支払額を全費目で合計した額とする。
- 負担額は、分担計算におけるその参加者の配分額を全費目で合計した額とする。
- 差額は `立替額 - 負担額` とする。
- 差額が正の参加者は受取側、負の参加者は支払側、0の参加者は精算不要として表示する。

## 8. 最終送金案

- 精算グループ内の全費目から参加者ごとの差額を計算し、相殺する。
- 差額が0の参加者は送金案に含めない。
- 支払側から受取側への送金として、送金元、送金先、金額を表示する。
- 金額の合計が一致することをBEで検証する。
- 送金案は費目・参加者の変更時に再計算する。
- V1では送金案を記録・確定・支払い確認しない。表示時点の費目から都度導出する。
- 差額を相殺し、数学的に送金回数が最小となる送金案を生成する。
- 同じ最小送金回数となる送金案が複数ある場合は、各案の送金を「送金元の参加順、送金先の参加順、金額」の順で並べ、辞書順で最も早い案を採用する。

## 9. 画面と操作

| 画面 | 主な内容 |
| --- | --- |
| ログイン開始 | Discordログインを開始する。ログイン済みなら精算グループ一覧へ進む。 |
| 精算グループ一覧 | 参加中の精算グループ一覧と作成への導線。 |
| 精算グループ詳細 | 精算グループ名、参加者への導線、費目一覧、最終送金案。 |
| 参加者管理 | ユーザー名検索、追加、有効化・無効化。 |
| 費目作成・編集 | 内容、総額、メモ、立替内訳、参加者ごとの重みの入力と分担額プレビュー。 |

- FEは入力中の分担額を即時プレビューしてよい。
- 保存後は、BEが返した確定値を表示する。
- APIの読み込み中、保存中、入力エラー、認可エラー、通信失敗を利用者へ表示する。
- UIはモバイルを主な利用環境として設計する。

### 9.1 共通UI方針

- 画面はスマホ幅を基準に設計する。PCではスマホ幅の画面領域を中央配置して表示する。
- 一覧は表形式を基調とする。金額は右寄せで表示し、表の見出しには淡い背景色と罫線を用いる。
- 破壊的な操作である費目削除と参加者の無効化は、確認ダイアログを表示してから実行する。

### 9.2 精算グループ詳細

- 主タブは「支払い」と「精算結果」の2つとする。
- 参加者管理は、グループ詳細の参加者導線から別画面で開く。「参加者・重み」タブは設けない。
- 「支払い」タブでは、費目を内容、立替額、編集操作の表として表示する。費目の追加は画面下部の固定ボタンから行う。
- 負担者と重みの設定は、各費目の編集画面で行う。

### 9.3 費目作成・編集画面

- 内容、総額、メモ、立替内訳、負担者・重みを1画面で編集できるようにする。
- 負担者・重みは、候補参加者ごとの数値入力欄として表示する。チェックボックスは使用しない。
- 重みの入力欄には0を初期表示する。0は負担対象外、0より大きい値は負担比率を表す。
- 新規作成時は立替者の重みを1、その他の候補参加者の重みを0とする。

### 9.4 精算結果タブ

- 現在の費目・参加者・重みから計算した結果であることを表示する。
- ログインユーザーに関係する送金がある場合は、その送金先または受取元と金額を「あなたの精算」として表の上部に表示する。送金がない場合は精算不要と表示する。
- 全員分の最終送金案を、送る人、受け取る人、金額の表として表示する。
- 参加者別の立替額、負担額、差額の集計表は表示しない。
- V1では未精算・精算確定・精算済みなどのステータス、送金案の確定操作、支払い確認操作を設けない。

## 10. FE/BE境界

| 領域 | nkmz（BE） | nkmz-seisann-web（FE） |
| --- | --- | --- |
| 認証・認可 | Discord OAuth、Cookie/JWT、参加者判定 | ログイン開始、認可失敗の表示 |
| データ | PostgreSQLへの保存、取得、整合性検証 | API呼び出し、表示・入力状態 |
| 計算 | 分担額、端数、個人別集計、送金案の確定計算 | 入力中のプレビュー |
| Wallet | 将来の連携を実装 | 将来の連携結果を表示 |

APIの具体的なURL、リクエスト/レスポンスJSON、エラー形式は、BE実装タスクに入る前に別途API仕様として定義する。

## 11. V1の対象外

- 旅行予定表
- 領収書・レシート画像
- Walletイベントの自動作成と支払い確認
- 送金案のコピー、共有リンク
- オフライン入力・同期
- 費目の変更履歴
- 複数通貨、為替、小数単位
